# Theory Assignment Answers

Written in simple, professional English so you can say them in an interview.

## 1. What is NPM?

NPM (Node Package Manager) is a tool and online registry for installing and managing JavaScript packages. It lets me download libraries like React, keeps track of them in `package.json`, and runs project scripts such as `npm start`. Despite the name, it doesn't "manage packages" only for Node, since it's used for frontend projects too.

## 2. What is Parcel/Webpack? Why do we need it?

Parcel and Webpack are **bundlers**. They take all my files (JS, CSS, images, and the npm packages I import) and combine them into a small number of optimized files that the browser can load.

We need them because:

- Browsers can't resolve npm packages on their own.
- They minify and optimize code for production.
- They provide a dev server, hot reloading, and caching.
- They convert modern code (JSX, newer JS) into code that browsers understand.

## 3. What is `.parcel-cache`?

A folder where Parcel stores the results of previous builds. On the next build, Parcel reuses the cached work and only rebuilds the files that changed, so rebuilds are much faster. It is generated automatically, so it should go in `.gitignore`. If you see stale or strange errors, deleting it is a common fix.

## 4. What is `npx`?

`npx` runs a package from the npm registry or from `node_modules` **without installing it globally**. For example, `npx parcel index.html` runs the Parcel version installed in the project. `npm` installs packages, and `npx` executes them.

## 5. `dependencies` vs `devDependencies`

- **dependencies:** packages the app needs to run in production, such as `react` and `react-dom`.
- **devDependencies:** tools needed only during development, such as `parcel`, `eslint`, and `jest`.

Install dev tools with `npm install -D <package>`.

## 6. What is Tree Shaking?

Tree shaking is the process of **removing unused code** from the final bundle. If I import a whole library but use only one function, the bundler includes only that function. This makes the bundle smaller and the site faster. It works best with ES modules (`import`/`export`).

## 7. What is Hot Module Replacement (HMR)?

HMR updates the changed part of the app in the browser **without a full page reload**. When I save a file, only that module is replaced, and the page keeps its current state. This saves time during development.

## 8. Five superpowers of Parcel (three explained)

1. **Zero configuration:** it works out of the box.
2. **Hot Module Replacement**
3. **Caching (`.parcel-cache`)**
4. **Tree shaking and minification**
5. **Automatic image optimization and code splitting** (also supports a local HTTPS dev server and good error diagnostics)

**In my own words:**

- **Zero configuration:** I don't have to write long config files like I would with Webpack. I just point Parcel to `index.html` and it figures out the rest.
- **HMR:** when I change my code and save, the browser updates instantly without reloading, so I can see results quickly and don't lose the app's state.
- **Caching:** Parcel remembers what it built before. After the first build, it only rebuilds the files I changed, so the dev server starts and updates faster.

## 9. What is `.gitignore`? What to add and not add?

`.gitignore` is a file that tells Git which files and folders to **leave out of version control**.

**Add:**

- `node_modules`
- `dist`
- `.parcel-cache`
- `.env` (secrets and API keys)
- Log files and OS files like `.DS_Store`

**Do not add:**

- `package.json`
- `package-lock.json`
- Source code
- `index.html`

The rule: ignore anything that can be **regenerated** or that is **private**. Keep everything needed to rebuild the project.

## 10. `package.json` vs `package-lock.json`

- **package.json:** describes the project and lists dependencies with **version ranges** (like `^19.0.0`). I edit it (or npm does when I install).
- **package-lock.json:** generated by npm, and records the **exact versions** of every package, including sub-dependencies, so every developer gets the same setup.

## 11. Why not modify `package-lock.json`?

It is auto-generated and holds exact versions and integrity hashes for the whole dependency tree. Editing it by hand can break the consistency, cause version mismatches, or create "works on my machine" bugs. If a change is needed, change `package.json` and let npm update the lock file by running `npm install`.

## 12. What is `node_modules`? Should we push it to Git?

`node_modules` is the folder where npm stores all the installed packages and their dependencies. **No, we should not push it to Git.** It's very large, it can be recreated at any time using `package.json` and `package-lock.json` with `npm install`, and it can contain machine-specific files. Add it to `.gitignore`.

## 13. What is the `dist` folder?

`dist` (distribution) is the folder where Parcel puts the **final, optimized build** of the app: minified JS, CSS, and assets, ready to deploy. It is generated automatically, so it should be in `.gitignore`.

## 14. What is `browserslist`?

Browserslist is a configuration that tells tools like Parcel, Babel, and Autoprefixer **which browsers the app should support**. Based on this list, the tools decide which CSS prefixes and JS transformations are needed. It can be set in `package.json`:

```json
"browserslist": ["last 2 versions"]
```

Supporting fewer or newer browsers means smaller bundles.

## 15. Vite vs Webpack vs Parcel

|                  | Webpack                | Parcel                             | Vite                                    |
| ---------------- | ---------------------- | ---------------------------------- | --------------------------------------- |
| Configuration    | Heavy, very flexible   | Almost zero                        | Light                                   |
| Dev server speed | Slower on big projects | Fast, with caching                 | Very fast (native ES modules)           |
| Best for         | Large, custom projects | Quick setups, small to medium apps | Modern projects, now the common default |
| Learning curve   | Steeper                | Easy                               | Easy                                    |

Webpack is the most customizable and widely used in older projects. Parcel is the easiest to start with. Vite is currently very popular for new React projects because of its speed.

## 16. Caret (`^`) vs Tilde (`~`)

- **`^1.2.3` (caret):** allows updates that don't change the **major** version, so it accepts `>=1.2.3` and `<2.0.0`.
- **`~1.2.3` (tilde):** allows only **patch** updates, so it accepts `>=1.2.3` and `<1.3.0`.

Caret is the npm default. Tilde is stricter and safer. (Special case: with `0.x` versions, `^0.2.3` stays below `0.3.0`.)

## 17. Script types in HTML (MDN)

- **Classic `<script>`:** the default. Blocks HTML parsing while it downloads and runs.
- **`type="module"`:** treats the file as an ES module, so `import`/`export` work. It is deferred by default.
- **`async`:** downloads in parallel and runs as soon as ready, with no guaranteed order.
- **`defer`:** downloads in parallel and runs after the HTML is parsed, in order.
- **`nomodule`:** runs only in old browsers that don't support modules.
- **`type="importmap"`:** maps module names to URLs.
- **Data blocks (e.g. `type="application/json"`):** not executed, used just to store data.

Since you're using Parcel, you'll mainly use `<script type="module" src="App.js"></script>`.
